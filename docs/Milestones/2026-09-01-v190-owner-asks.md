# v1.9.0 — the late-evening owner asks: calendar follow, dock re-layout + User Notes, developer Viewer toggle, dashboard navigation

**Date:** 2026-09-01 · **Version:** v1.9.0 · **Branch:** `development` (`/preview/`)
**Backlog:** TODO §3 item 32 (all four), item 30 first half (User Notes)
**Suite:** `tests/test-v190.js` (36 checks)

Four asks from the 2026-09-01 late-evening handoff, in plain language:

## 1. Calendar resize follows the mouse into other weeks

Dragging a phase's edge on the project calendar always tinted the day cells
correctly across week rows, but the phase bar itself only stretched inside the week
you grabbed it in — moving the mouse to the week above or below left the bar behind.

Now the moment the drag leaves its home week, the calendar repaints the phase live
at the snapped span (a paint-time override, `NPV_CAL_RZ`) — the bar jumps from week
to week under the mouse, in both directions, growing new week rows when the span
needs them. Inside the home week the original smooth pixel stretch is unchanged.
Merged roster-twin bands stay merged during the follow. Known ceiling (ledgered):
you can't drag past the last painted week — there are no day cells below it to
hover; long extensions belong to the Gantt or the date fields.

## 2. My Dashboard dock: stacked column + User Notes

The dock's four columns were Working on | Milestones | Notes | Time off. Now
**Milestones and Notes stack in one column**, and a new **User Notes** column sits
at the far right: a personal multi-line scratch pad, saved to your own staff row
(`personalNotes` — the first half of TODO item 30). It saves on blur through the
normal optimistic staff sync, and works for viewers too: this is the self-row
exception the v1.8.0 people-edit guard promised (`savePeople(list, true)`).
Personal by spec — the column only exists on **your own** dashboard; someone else's
Summary never shows it. ⚠ Robert creates the `personalNotes` column (multi-line
plain text) on `ShopTimeline_Staff`; until then a save surfaces the normal
sync-error toast. "Listening to" (item 30's other half) is still open.

## 3. The developer's Viewer toggle

The staff `admin` column accepts a third value: **`dev`** marks a developer — a
full admin whose toolbar gains a **Viewer** button next to the version number (top
right, visible on every page). One click previews the app exactly as a non-admin
sees it: `isAdmin()` answers false everywhere, so every real door closes — create
buttons gone, fields flattened, Lock Dates forced on (and restored on exit), edits
refused. The state is remembered per tab and the button stays lit while active.
Robert types `dev` onto his row directly on the list; the People editor never
assigns it, but People-page saves preserve it (a demote deliberately drops it —
re-typing restores it, ledgered).

## 4. My Dashboard navigates

Clicking My Dashboard from the People or Clients page (or a project page) used to
arm the dashboard *behind* the open page — it only appeared after the page was
closed. `enterDash` now walks the hash back to the timeline (`#/`), so the click
lands **on** the dashboard, the same way every other page navigation works.

## Evidence

Verified in a real browser against a stubbed build (no tenant needed): mid-drag
screenshots show the bar painted in the pointer's week with the tint; the dock
renders Working on | Milestones+Notes | Time off | User Notes; the Viewer toggle
flips the whole app to the viewer experience and back with Lock Dates restored;
People page → My Dashboard lands on the dashboard. Suite `test-v190.js` covers all
four (36 checks) including the privacy rule (another person's notes never render)
and the `dev` value surviving People-page saves.
