# v1.20.0 — Owner batch: dept-true assignments, holidays, undo/redo, help pages

**Date:** 2026-09-03 · **Version:** v1.20.0 · **Branch:** development

The batch of owner asks from the morning after the all-staff demo (09-03), plus the
Help section's first self-serve pages.

## What changed

- **Crew pickers cull to the department.** The phase inspector and the task modal only
  offer people whose Company Data → People departments match the phase (coarse people
  ids — a CNC phase offers everyone tagged DFAB). Install still picks from the whole
  staff; a department nobody is tagged with falls back to the old, wider pool. On the
  global timeline's department lens, a person from another department no longer earns a
  lane just by being crewed on a bar there — the bar files under the first member who
  *is* in the department, else the "—" lane.
- **Holidays wear their names.** They were already baked into the schedule and greyed
  like weekends; now each one gets a small grey name pill (the TODAY-pill anatomy) at
  the top of its column on both the global timeline and the project chart, plus a
  tooltip on the date header.
- **Undo *and redo*, everywhere.** New ↩ ↪ toolbar buttons (global row, every page)
  with hotkey tooltips; Ctrl+Z / Ctrl+Y and ⌘Z / ⌘Y (⌘⇧Z too). Root cause of the
  phantom "Nothing to undo": the 90-second poll wiped the undo stack whenever SharePoint
  echoed back our own save's updatedBy/updatedAt stamps — now only a real data change
  clears history. Drafts get redo via state snapshots; a draft's empty stack no longer
  falls through and silently undoes an unrelated timeline edit.
- **Milestones and Notes lead the project chart.** Row 0 is Milestones, row 1 is Notes,
  phases below — markers no longer ride phase rows or hide at the bottom.
- **Help ▸ Release notes** — plain-language per-version notes (curated in the
  `RELEASE_NOTES` const; add an entry each release).
- **Help ▸ Open issues** — the bug-report modal became the left pane of a page
  (Company Data chrome); the right pane lists every filed report as a deliberately
  vague one-liner (kind + summary + date, no names).
- **Help ▸ Bug reports (dev)** — developer-only page with each report in full (reporter,
  email, version, description — the same content as the recipient email).

## Notes / ceilings

- Open Issues has no "resolved" state — the ShopTimeline_Feedback list has no status
  column; every filed report shows. Add a status column (schema change, needs approval)
  if the list ever needs triage.
- People/Clients edits are still outside the undo system (they have their own
  Save-with-confirm flow).
- The month-calendar view greys holidays but doesn't show name pills.
- Right-clicking the new Milestones/Notes gutter rows offers the date-scoped menu
  (milestone/note), not a department menu — by design, there is no department there.
