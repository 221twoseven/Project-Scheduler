# 2026-09-02 — v1.18.1: the September audit round (16 review findings fixed)

A high-effort code review of everything on `development` since `main` (v1.0.1 →
v1.18.0) surfaced 16 confirmed defects; all 16 are fixed in this release. No schema,
no Entra, no new columns — pure app and test-infrastructure fixes.

## What was broken, what changed

**Permissions**
- The **Subtasks viewer grant unlocked the entire Edit Phase modal** — a
  subtasks-only viewer could move phase dates, change the department, and click
  Delete Phase (verified end-to-end in the harness: the delete really removed the
  SharePoint row). The phase's own fields now follow the **Phases** door; only the
  Milestones block and Save ride the subtasks grant, and Delete Phase is
  phases-gated in CSS plus a belt check in the handler. The `S` key could also
  create a department's **primary** bar (a phase) under the subtasks grant — refused
  now unless the phases door is open.
- **Booting straight onto a project page skipped `applyPerms` entirely** (viewer
  chrome off, delete buttons visible, dev toggles hidden). `applyRoute` now runs it
  at every door. Reopening the phase modal after a grant flip also un-sticks its
  fields (they used to stay disabled).

**Sync resilience**
- **The staff poll could revert a save that started during its own round-trip** —
  the residue of the owner's "my merges reverted" report that v1.15.2 didn't fully
  close. The staff branch now re-checks after its `await` (the REV90 lesson),
  keyed on a new `PEOPLE_GEN` counter.
- **Merge-duplicate had no ordering** — a failed roster PATCH after a successful
  assignment scrub left a half-merged state. The scrub now runs only once the
  roster save lands; a parked failure carries it as the retry's continuation.
- **Failed client and App-Settings writes were unrecoverable** — the sync pill said
  "click to retry" and did nothing for those kinds, `beforeunload` didn't warn, and
  a reload silently lost the edit. Both now park like staff does and replay from
  the pill; both count in the close-tab warning.
- **Leaving Company Data via × / All Projects silently discarded a mid-edit record
  and stranded `CD_EDIT`**, which short-circuited every 90-second poll tick until a
  Company Data page was revisited. Both exits now confirm like Esc, and every
  route change away drops the buffer.

**View state and display**
- A v1-era stored `view:'month'` (5 px/day, the widest scale) collided with the new
  `month` step (≈40 px/day) and reopened ~8× more zoomed-in after an upgrade —
  mapped to `month3` for fit-less snapshots.
- The seeded **Everything** view left a live client filter applied (`client` was
  missing from `defaultViewState`).
- Search stopped matching **roster names** once a nickname was set (v1.15.0) —
  it now matches both.
- The wordmark now goes home — timeline, person summary dropped — from **any**
  route in one click.
- Dashboard **Notes** resolve legacy `who` names through `canonName` like every
  other person join.
- Unnamed calendar milestone bands read **"Untitled milestone"** instead of a bare
  `"Fabrication: "`.
- Dragging the People-page **pane split** reseats the column grips live (they used
  to strand at stale positions).

**Test infrastructure**
- `tests/run.js`'s self-skip detector only knew one of the two skip-message styles;
  on the frozen reference it reported "72/72 passed, 44 skipped" when the true
  self-skip count was ~67 — 23 suites were folded silently into the passed tally.
  The detector now matches both styles (root fix if a third style ever appears:
  an exit-code protocol).
- `tests/test-v4-views.js`, `test46.js`, `test50.js` had been re-saved with a BOM
  and double-encoded UTF-8 (`—` → `â€"`), which corrupted assertion labels and
  defeated the skip detector on the one suite it was written for. Encoding
  restored.
