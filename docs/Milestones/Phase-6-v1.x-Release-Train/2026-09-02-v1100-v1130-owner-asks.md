## v1.12.0 — "Listening to" (item 9; item 30's second half, revised spec)

## v1.13.0 — the People page mirrors Employee Contacts (item 4)

An admin-only **Import from Employee Contacts** button reads the HR list (READ-ONLY —
never written, never schema-touched; Pay Type and PersonalEmail never even read) and
mirrors it into the roster in one confirm: active newcomers are added (Current Title
→ role, phone, work email, department mapped to an app id — unmapped strings reported,
never guessed), matched people take HR as master for title/phone/status while curated
departments and existing emails are kept, non-active rows never create people, and
nothing is auto-removed. Join key = work email with an exact-name fallback — the same
`meName()` identity chain, so after one run every M365 sign-in that exists on the HR
list pairs with a roster row. The `status` column (vocabulary = the HR Status values)
is probed live and starts syncing the run after Robert creates it. Field names
resolve `_x0020_`/case/space-insensitively, so the HR list's internal names don't
matter. Re-runs are idempotent.

**Answer to the owner's access question:** every TwoSeven M365 login can open the app
(single-tenant Entra app, admin-consented scopes). Pairing to roster data is by work
email; the import makes that pairing complete and consistent. Unmatched sign-ins are
viewers with an unresolved dashboard — the import report (console + confirm text) is
where mismatches surface.
