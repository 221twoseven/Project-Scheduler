# 2026-09-08 — A Project Manager is required to create a project

**Date:** 2026-09-08 · **Version:** 1.20.8 · **Branch:** development → main (PR #43) ·
**Commits:** `94eb2e3`, `504f04e`, `2be9c6e` · Record written 2026-10-15 (item 23).

## What changed

- **Create needs a Project Manager.** Without one, Create refuses and marks the Team box
  red, the same way it does for a missing name or install date. The draft opens with no
  PM ticked.
  - The first build that day made the creator the default PM instead; the owner reversed
    it the same day, because a default is easy to leave wrong.
  - The rule applies only while the roster has a PM to pick. An empty staff list has no
    PM box, so a fresh install would otherwise dead-end.
- **My Dashboard lists every row** — milestones, working-on bars, time off, notes. A long
  column scrolls instead of hiding rows behind "+N more".
- **An untouched New Project page leaves quietly.** The clean-draft snapshot is now taken
  after the form renders, so it no longer asks "Discard this unsaved project?".

Guarded by `test-v1208` (draft page, saved page, dashboard). It had skipped itself
silently from v1.47.0 until #153 fixed its check on 2026-10-14.
