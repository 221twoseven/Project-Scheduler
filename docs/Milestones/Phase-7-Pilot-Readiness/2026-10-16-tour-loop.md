# The tour's 6 ↔ 7 loop, and "Don't show again" — v1.49.0 (2026-10-16)

**TODO item 3**, tracker #7 (reported on v1.23.0, 2026-09-24). PR #166.

## What was wrong

The report: the Help walkthrough "seems to be getting stuck in a loop between steps 6 and 7".

Step 7 is the hand-off step. It highlights **+ New Project** and asks you to click it, and
the tour carries on from the new project page. To make you click the real button, the tour
**hid its own Next button** on that step. That left **Back** in the card's bottom-right
corner, the spot where Next sits on every other step.

So anyone who moves through the tour by clicking the card's right-hand button did this:
step 6, Next → step 7, the same corner (now Back) → step 6, Next → step 7, and round again.
It isn't browser-specific: it's the tour's own layout.

**How it was proved.** A script drove headless Chrome with real mouse clicks (Chrome's
DevTools protocol, not simulated events):

- clicking the card's right-hand button each time, the v1.23.0 build (the reporter's) and
  the current build both looped 6 → 7 → 6 → 7 forever;
- clicking Next normally, and **+ New Project** on step 7, walked all 14 steps fine, at
  1600, 1280 and 1024 pixels wide, from the timeline, a saved project, a draft, the People
  page and My Dashboard, as admin and as a viewer;
- pressing Enter on a focused Next moved exactly one step each time.

The other suspects were checked and cleared: Enter firing twice, the resize handler
re-wiring the hand-off, the hand-off landing on the wrong page, the first-visit auto-run
re-triggering, and Back after the hand-off.

## What changed

- **Next stays on step 7** and presses + New Project for you, the same thing Enter
  already did. The bottom-right button always moves forward now.
- **A missing step is skipped, never bounced.** If a step's target has gone by the time
  you reach it (or isn't drawn on screen), the tour drops that step and keeps going the way
  you were going. Before, it would have crashed or spotlit an empty corner.
- **The first-visit auto-run can't restart a tour that's already up**, and won't start
  if you've already left the timeline.
- **Don't show again** (owner-approved wording) sits beside Skip tour. It ends the tour
  and stops the tour ever starting by itself for you, on any computer or browser. Help ▸
  Take a tour still runs it.

The card grew from 300 to 360 pixels wide to fit four buttons: Skip tour and Don't show
again on the left, Back and Next on the right.

## How "Don't show again" is stored

There's no new SharePoint column. The app writes one row to the existing
`ShopTimeline_Config` list: **Title** `tour.off.<your sign-in, lower-case>`, **value**
`1`. The first-visit check reads it alongside this browser's own "tour seen" flag.

- The write is quiet: no sync-pill flicker and no toast.
- Viewers can use it too.
- If the Config list can't be reached, the button still ends the tour, and this browser's
  "seen" flag stops it here, with no error.
- App settings never lists these rows. That page shows only its own switches.

## Limits and follow-ups

- **Safari was not tested.** There's no Mac here. The cause is in the tour's own logic,
  not the browser, so the fix applies there too.
- Edge and Chrome share an engine. Firefox isn't installed on this machine.
- One Config row per person who presses the button. Small, but it does grow with the
  team.
